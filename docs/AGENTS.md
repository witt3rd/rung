# docs — conventions

1. A document about the whole language, or governing it, is at `docs/` root.
   Props (`*-props.md`) and `conformance.md` are generated by
   `cargo run -p rung-doctrine --bin render` and never edited by hand (CI runs
   `render --check`); notes (`*-notes.md`, `triage.md`) derive them and sit
   beside them. Where an informative document disagrees with a normative one,
   the normative one wins.
2. A document with one reader task is a guide and lives in `guides/`. A
   document that states a contract is reference. Unbuilt designs are design.
3. A document about one crate is named for the crate (`rung-<crate>.md`); the
   crate's own `AGENTS.md` is its front page and links here. Per-theory pages
   live in `rung-std/`.
4. Dated measurements, briefs and evidence are records in `records/`,
   append-only; see `records/AGENTS.md`. Never edit them after the fact.
5. Do not restate what code, `--help` text or a generated file already says;
   link to it. No hand-written counts.
6. Files starting with `_` are tooling, not documents.

The Rust API reference is rustdoc; the host's wire contract is prose in
`reference/rung-host-doors.md` (with `rung-host-queue.md`, `rung-gateway.md`, `rung-redaction.md`).
